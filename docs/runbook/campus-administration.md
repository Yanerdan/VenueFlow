# 校园管理端运行手册

## 启动

```powershell
.\scripts\local-dev\start.ps1
python -m http.server 3000 --directory venueflow-web
```

脚本会启动 MySQL、Redis、RabbitMQ、Elasticsearch、七个应用服务，执行 Flyway 迁移，写入演示资源，并创建本地管理员 `campus.admin / Campus-Admin-2026!`。

如果此前已有 `secrets/local-dev/local-dev.env`，启动脚本也会补充本地管理员配置。修改管理员配置后需要重启 Auth Service，并重新登录以获得包含新角色的 JWT。

## 工作区

- `http://127.0.0.1:3000/`：师生申请人工作区。
- `http://127.0.0.1:3000/admin.html`：学校管理工作区。

管理端使用与申请人端相同的 `sessionStorage` 会话；在同一标签页从用户端进入管理端时不需要重复登录。`APPLICANT` 不能访问管理端，`APPROVER` 可审批并查看人员目录，`RESOURCE_MANAGER` 可维护资源，`SYSTEM_ADMIN` 拥有当前全部管理能力。系统管理员可直接在“人员目录”修改平台角色；修改后该账号需重新登录才能获得新权限，系统不允许管理员降级自己的账号。

申请人可在注册时填写学工号、人员类型、院系、电话和邮箱，也可在“个人资料”中随时补全。管理端“人员目录”支持按姓名、学工号或院系查询；审批列表会优先展示申请人姓名和院系，缺失字段明确显示“待完善”。

场地申请必须填写活动名称、用途、联系人和联系电话，可补充设备或布置说明。审批人员从“查看并审批”打开详情；通过时意见可选，驳回时原因必填，处理结论会回显到申请人的申请详情。

资源卡片可维护归属部门，并从具备 `APPROVER` 或 `SYSTEM_ADMIN` 角色的人员下拉列表中选择审批人。`DIRECT` 由一名审批人直接处理；`TWO_STAGE` 要求初审人与终审人不同。新申请会快照该配置；初审通过后申请仍为待审批并推进到终审，终审通过后才确认。`APPROVER` 只能查看当前节点分配给自己的申请，`SYSTEM_ADMIN` 可处理全部申请。未配置审批人的历史资源仅由系统管理员兜底处理。

申请详情会显示“当前级 / 总级数”和按时间排序的审批轨迹。任一级驳回都会立即结束申请并释放容量；资源后来修改策略不会影响已提交申请。

“运营报表”展示申请总量、待审批量、审批通过率、预约参与人数、资源申请排行、归属部门分布和最近审批记录。`SYSTEM_ADMIN` 查看全局统计，`APPROVER` 只查看分配给自己的数据；报表直接基于持久化预约快照生成。

## 业务状态

| 状态 | 用户端含义 | 管理端动作 |
|---|---|---|
| `PENDING_CONFIRMATION` | 等待审批 | 通过或驳回 |
| `CONFIRMED` | 审批通过 | 签到核销或取消 |
| `COMPLETED` | 已完成使用 | 无 |
| `CANCELLED` | 已撤回/取消 | 无 |
| `EXPIRED` | 审批窗口超时 | 无 |

管理审批复用 Booking 现有可靠状态机、容量释放和 Outbox 通知，不维护第二份预约事实。

## 验收

```powershell
.\scripts\local-dev\status.ps1
.\scripts\local-dev\smoke.ps1
```

`smoke.ps1` 会创建一次性申请人、维护校园资料、临时提升为审批人，为演示资源配置两级审批和预约规则并提交完整用途申请，依次完成初审和终审，再通过规则协作响应、审批轨迹、运营报表、人员目录、搜索、通知、令牌刷新和退出完成全链路验证。验收账号最终会恢复为 `APPLICANT`。

资源预约规则位于管理工作台的“资源管理”卡片中：

- 申请须知最多 1000 字；
- 最少提前 0–720 小时；
- 最多提前 1–365 天；
- 单次最长 15–1440 分钟。

规则更新采用资源版本号控制。若页面停留期间资源已被其他操作修改，刷新后重新提交即可。

## 常见问题

- 管理端提示没有权限：退出后使用管理员重新登录；旧令牌不会自动获得新角色。
- 管理端没有资源：运行 `scripts/local-dev/seed.ps1`。
- 浏览器请求失败：确认前端通过 `127.0.0.1:3000` 访问，Gateway 为 `127.0.0.1:8080`。
- Auth 启动失败：确认 MySQL 可用，且 Auth 的数据库和 JWT 密钥环境变量齐全。
- 新建资源后用户端不可见：资源默认是草稿，需要在资源管理中点击“发布”。
