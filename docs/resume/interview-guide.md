# VenueFlow 面试指南

## 1. 为什么使用微服务，而不是单体？

项目的目的之一是展示服务边界和分布式协作，因此按身份、人员、资源、预约、通知、搜索拆分。拆分依据是状态所有权和一致性边界。若是小型真实团队的首版，我会优先采用模块化单体，等独立扩缩容或团队边界出现后再拆分。

## 2. 如何避免同一申请被重复创建？

客户端为命令提供幂等键，服务端保存键与业务结果。相同请求重试返回既有结果，冲突请求不能复用同一键。幂等只解决重复命令，容量并发仍由 Resource 的原子台账约束。

## 3. 两个服务之间为什么不用分布式事务？

预约流程可以接受短暂中间状态，但必须可恢复。项目采用预占、确认/释放、超时与对账补偿，避免引入强耦合的两阶段提交。代价是需要显式状态机、幂等接口和运维可见性。

## 4. Outbox 解决了什么？

它解决数据库提交和消息发布无法原子完成的问题。业务事实与待发布事件同事务写入，发布器可重试；因此交付可能重复，消费者必须按事件标识幂等。

## 5. RabbitMQ 挂了还能预约吗？

核心预约可以提交，Outbox 记录保留。消息恢复后继续发布，通知和搜索会短暂滞后。这是把核心交易可用性置于派生能力实时性之上的权衡。

## 6. Elasticsearch 数据不一致怎么办？

Elasticsearch 只是读模型，资源服务仍是权威来源。投影处理版本或事件标识，失败可重试，并能从资源事实重新建立索引。

## 7. 审批模板修改后，进行中的申请怎么办？

申请提交时把策略复制为有序审批步骤快照。旧申请继续走旧链，新申请读取新模板。这保证历史审批责任可解释、可审计。

## 8. 为什么 OIDC 登录后还要维护本地用户？

IdP 只提供外部身份。系统仍需本地资料、组织成员关系、平台角色和业务状态。使用 issuer + subject 建立稳定映射，避免把可变化的邮箱当主身份。

## 9. PKCE 的价值是什么？

浏览器生成 verifier，只发送 challenge 到授权请求；回调拿到 code 后必须携带 verifier 换取令牌。即使授权码被截获，没有 verifier 也难以兑换。

## 10. 全量和增量组织同步如何共存？

全量同步用于建立基线和纠偏，增量同步用于日常变更。外部组织和人员标识作为幂等键；真实接入还应加入游标、水位、删除策略、签名校验和失败重放。

## 11. Gateway 做了授权，服务为什么还要检查？

Gateway 适合统一认证和粗粒度入口控制，但业务规则属于领域服务。审批服务必须验证当前节点、审批人和组织范围，不能只信任“请求经过网关”。

## 12. 如何处理数据库结构演进？

各服务拥有独立 Flyway 历史，只做可重复部署的前向迁移。跨服务协议采用先扩展、后迁移、再收缩的兼容过程，避免生产者和消费者必须同时发布。

## 13. 测试策略是什么？

领域规则用单元测试，Web/持久化边界用组件测试，仓库级验证执行 Maven 质量门禁与前端 Node 测试，真实依赖链通过本地启动后的 smoke 脚本验证。面试时应区分测试数量与覆盖质量。

## 14. 为什么前端没有使用 React/Vue？

当前前端选择原生 ES Modules，减少构建和运行时依赖，让作品聚焦完整业务链和后端工程。代价是复杂状态管理和组件复用能力有限；若继续扩大团队和页面规模，会迁移到 TypeScript + 成熟组件框架。

## 15. 项目最大的不足是什么？

尚未完成真实学校联调、目标容量压测、安全审计和生产编排。这些不能靠合成数据证明。项目明确保留边界，同时提供 OIDC、组织同步、可观测配置和运行手册作为后续落地接口。

## 16. 如果再做一轮，优先改什么？

优先级取决于目标：求职展示会补自动化演示视频和部署环境；真实试点会先做 IdP/组织源联调、安全威胁建模、备份恢复与容量基线；前端团队化则会引入 TypeScript、组件系统和端到端测试。

## 17. Nacos 在项目里到底负责什么？

负责两件事：配置中心保存公共、非敏感的运行参数；注册中心保存服务名到健康实例的映射。Gateway 和 Booking 按服务名发现下游，实际鉴权、路由和业务仍由 Gateway 与领域服务完成。数据库密码和 JWT 密钥不进入 Nacos。

## 18. 为什么保留静态模式，没有强制所有环境使用 Nacos？

服务治理是运行能力，不应成为本地开发的单点依赖。静态模式更容易排查单服务问题，治理模式用于验证配置加载、注册发现、负载均衡和故障切换。两种模式共享业务代码和数据库，因此可以渐进引入、快速回退。

## 19. 你如何证明双实例真的完成了故障切换？

脚本先通过 Nacos API确认两个 Resource 实例健康，再携带 JWT 和固定 Trace ID 经 Gateway 读取资源；随后只终止第二实例的受管 PID，等待 Nacos 健康实例数变为一，再次经 Gateway 读取，最后在 `finally` 中重启并等待恢复到两个实例。该结论只覆盖本地功能性故障切换，不代表生产 SLA。

## 20. 为什么不把数据库密码直接放进 Nacos？

配置中心不天然等同于密钥管理系统。仓库中的 Data ID 只保存非敏感默认值，数据库凭据、Nacos 管理密码和 JWT 密钥通过被忽略的本地环境文件或进程环境注入。真实生产应进一步接入专门的 Secret Manager、权限审计和密钥轮换。

## 21. Nacos 挂了，已经运行的服务还能工作吗？

短时间内可能依赖客户端已有的实例与配置缓存继续工作，但新实例注册、最新配置和服务列表更新会受影响，不能把它描述成完全无影响。当前项目只使用单节点 Nacos 做本地治理演示；生产环境需要 Nacos 集群、持久化存储、监控和恢复方案。
