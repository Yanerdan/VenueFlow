# 校园管理端运行手册

## 启动

```powershell
.\scripts\local-dev\start.ps1
python -m http.server 3000 --directory venueflow-web
```

脚本会启动 MySQL、Redis、RabbitMQ、Elasticsearch、七个应用服务，执行 Flyway 迁移，写入演示资源，并创建本地申请人 `campus.user / Campus-User-2026!` 与管理员 `campus.admin / Campus-Admin-2026!`。

如果此前已有 `secrets/local-dev/local-dev.env`，启动脚本也会补充本地管理员配置。修改管理员配置后需要重启 Auth Service，并重新登录以获得包含新角色的 JWT。

## 工作区

- `http://127.0.0.1:3000/`：师生申请人工作区。
- `http://127.0.0.1:3000/admin.html`：学校管理工作区。

管理端使用与申请人端相同的 `sessionStorage` 会话；在同一标签页从用户端进入管理端时不需要重复登录。`APPLICANT` 不能访问管理端，`APPROVER` 可审批并查看人员目录，`RESOURCE_MANAGER` 可维护资源，`SYSTEM_ADMIN` 拥有当前全部管理能力。系统管理员可直接在“人员目录”修改平台角色；修改后该账号需重新登录才能获得新权限，系统不允许管理员降级自己的账号。

申请人可在注册时填写学工号、人员类型、院系、电话和邮箱，也可在“个人资料”中随时补全。管理端“人员目录”支持按姓名、学工号或院系查询；审批列表会优先展示申请人姓名和院系，缺失字段明确显示“待完善”。

场地申请必须填写活动名称、用途、联系人和联系电话，可补充设备或布置说明。审批人员从“查看并审批”打开详情；通过时意见可选，驳回时原因必填，处理结论会回显到申请人的申请详情。

申请人可以按日期、人数、分类和关键词查找空间，开放时段按日期分组。空间收藏按当前账号保存在本浏览器，并可切换为“我的收藏”筛选。尚未提交的申请内容同样按账号保存；历史申请支持状态/文本筛选和“再次申请”。已通过申请可导出标准 `.ics` 日历文件；“改期”会明确提示并先撤回可取消的原申请，成功后保留申请信息并引导选择新时段，该过程不是原子换期。消息中心的已读状态只保存在当前浏览器，点击带申请编号的消息会定位到对应申请。

资源卡片可维护归属部门，并从具备 `APPROVER` 或 `SYSTEM_ADMIN` 角色的人员下拉列表中编排 1–5 级审批。每一级包含环节名称和明确负责人；新申请会快照该配置，逐级通过后才确认。`APPROVER` 只能查看当前节点分配给自己的申请，`SYSTEM_ADMIN` 可处理全部申请。旧的直接/两级配置继续兼容，未配置审批人的历史资源仅由系统管理员兜底处理。

## 校园身份与组织治理

Auth Service 支持 OIDC Authorization Code + PKCE。默认关闭，学校 IdP 管理员签发客户端后，在本地未跟踪环境文件中配置 `.env.example` 所列 `VENUEFLOW_OIDC_*` 变量。登录页会读取提供方就绪状态；配置不完整时明确显示不可用并保留本地演示登录，不会伪装成已联通。正式环境可将 `VENUEFLOW_AUTH_LOCAL_LOGIN_ENABLED=false` 关闭账号密码入口。

系统管理员可在“身份与组织”查看身份提供方状态、组织树和最近同步结果，并提交规范化 JSON 批次。`PARTIAL` 只更新批次内记录，`FULL` 会停用该来源中本批次未出现的组织和成员；`source + runKey` 保证重复调用幂等。同步产生的学工号、身份类型和主组织属于权威字段，个人资料页只能修改联系电话、邮箱等自助字段。

申请详情会显示“当前级 / 总级数”和按时间排序的审批轨迹。任一级驳回都会立即结束申请并释放容量；资源后来修改策略不会影响已提交申请。

“运营报表”展示申请总量、待审批量、审批通过率、预约参与人数、资源申请排行、归属部门分布和最近审批记录。`SYSTEM_ADMIN` 查看全局统计，`APPROVER` 只查看分配给自己的数据；报表直接基于持久化预约快照生成。

资源管理员可在资源卡片中修改名称、分类、位置、容量和用途说明，所有修改都携带资源版本号。向申请人展示的已发布资源必须同时具有名称、位置、正容量和归属部门；资料不完整的记录仍保留在管理端供修正。开放时段按本地日期分组并显示当前加载页的总数、开放数和关闭数；批量开放/关闭在明确确认后逐条携带版本号执行，遇到冲突会停止并刷新当前排期。时段表单支持按周重复 1–12 次，遇到冲突会停止后续创建并保留此前已成功的时段。

“申请审批”的“导出当前列表”会将当前授权范围和状态筛选下已加载的记录下载为 UTF-8 CSV，并对电子表格公式前缀进行安全转义。

## 业务状态

| 状态 | 用户端含义 | 管理端动作 |
|---|---|---|
| `PENDING_CONFIRMATION` | 等待审批 | 通过或驳回 |
| `CONFIRMED` | 审批通过 | 签到核销或取消 |
| `COMPLETED` | 已完成使用 | 无 |
| `CANCELLED` | 已撤回/取消 | 无 |
| `EXPIRED` | 审批窗口超时 | 无 |

管理审批复用 Booking 现有可靠状态机、容量释放和 Outbox 通知，不维护第二份预约事实。

## 验收

```powershell
.\scripts\local-dev\status.ps1
.\scripts\local-dev\smoke.ps1
```

`smoke.ps1` 会创建一次性申请人、维护校园资料、临时提升为审批人，为演示资源配置两级审批和预约规则并提交完整用途申请，依次完成初审和终审，再通过规则协作响应、审批轨迹、运营报表、人员目录、搜索、通知、令牌刷新和退出完成全链路验证。验收账号最终会恢复为 `APPLICANT`。

## 学期运营演示数据

`start.ps1` 默认调用 `seed.ps1`，装载一套合成的 2026 春季学期运营数据：

- 16 名分布在学院和职能部门的合成人员；
- 1 个绑定代表性申请、审批和消息历史的可登录申请人；
- 10 个教学、会议、活动、体育艺术和公共服务资源；
- 每个在用资源未来一个月的多个开放时段；
- 72 条跨约四个月的申请，覆盖已完成、已通过、待审批、驳回/撤回和超时；
- 与业务状态匹配的审批动作、意见和站内通知。

这些记录不对应真实师生或真实学校业绩。其保留标识分别为 `showcase-*`、`VF-CAMPUS-*` 和 `VF-SHOW-*`。重复执行：

```powershell
.\scripts\local-dev\seed.ps1
```

会稳定重建这些演示记录，同时保留其他用户、资源和预约。脚本还会触发搜索索引重建。

推荐从申请人账号开始验收：登录后应看到 6 条跨不同状态的个人申请、对应服务消息、完整校园资料，以及已解析为资源名称和使用时间的历史卡片。登录页的“快速体验本地演示”按钮只负责填入凭据，仍会经过正常 Auth 登录。

资源预约规则位于管理工作台的“资源管理”卡片中：

- 申请须知最多 1000 字；
- 最少提前 0–720 小时；
- 最多提前 1–365 天；
- 单次最长 15–1440 分钟。

规则更新采用资源版本号控制。若页面停留期间资源已被其他操作修改，刷新后重新提交即可。

## 常见问题

- 管理端提示没有权限：退出后使用管理员重新登录；旧令牌不会自动获得新角色。
- 管理端没有资源：运行 `scripts/local-dev/seed.ps1`。
- 浏览器请求失败：确认前端通过 `127.0.0.1:3000` 访问，Gateway 为 `127.0.0.1:8080`。
- Auth 启动失败：确认 MySQL 可用，且 Auth 的数据库和 JWT 密钥环境变量齐全。
- 新建资源后用户端不可见：资源默认是草稿，需要在资源管理中点击“发布”。
