# VenueFlow 5 分钟演示脚本

## 演示前

```powershell
.\scripts\local-dev\start.ps1 -Governance
python -m http.server 3000 --directory venueflow-web
.\scripts\local-dev\smoke.ps1
.\scripts\local-dev\governance-smoke.ps1
```

打开申请人端和管理端，确认页面顶部的合成数据说明可见。

## 0:00–1:00 · 产品定位

介绍 VenueFlow 解决的不是单一会议室预订，而是跨院系资源的发布、申请、审批与审计。快速展示申请人资源大厅和管理运营总览，让听众先看到完整产品形态。

## 1:00–2:00 · 申请人链路

1. 使用 `campus.user` 登录。
2. 按日期、人数和分类筛选，查看资源规则与可用时段。
3. 收藏资源，填写活动用途、联系人和参与人数并提交申请。
4. 打开“我的申请”，展示审批步骤、状态历史和消息跳转。

讲解点：重复点击由幂等键保护，人数和时长在占用容量前由服务端校验。

## 2:00–3:30 · 管理治理链路

1. 使用 `campus.admin` 进入管理端。
2. 在资源管理中展示归属组织、申请规则和 1–5 级审批配置。
3. 在申请审批中打开详情，展示有序审批轨迹并推进当前节点。
4. 展示组织架构、人员角色和审批人的来源。

讲解点：预约提交时保存审批快照，模板修改不会改变历史流程。

## 3:30–4:20 · 运营闭环

展示签到核销、通知中心、资源排期和运营报表；说明统计按管理员权限范围收敛，而不是所有审批人都能看到全校数据。

## 4:20–5:00 · 技术深挖入口

打开 README 架构图，先说明 Nacos 只承担配置与注册发现，Gateway 通过服务名路由到两个 Resource 实例；展示故障切换脚本结果。随后沿“Booking → Outbox → RabbitMQ → Notification/Search”说明最终一致性，以及容量台账、超时释放与对账如何处理跨服务失败。

## 推荐收尾

“这个项目当前是可完整演示的个人工程作品。它没有虚构真实学校上线数据，但把校园统一身份、组织治理、多级审批、分布式一致性和工程交付做成了可运行、可测试、可追踪的闭环。”
